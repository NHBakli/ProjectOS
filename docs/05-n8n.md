# 5. Déployer n8n

n8n officiel `2.44.5` (chart `1.17.0`). Adresse : `https://n8n.TON-DOMAINE`.

## Ce qui est installé

| Élément | Détail |
|---|---|
| Mode | Simple : une instance, base SQLite sur un volume de 5 Gio |
| Accès | HTTPS uniquement. HTTP redirige vers HTTPS. |
| Webhooks | Publics sur la même adresse, pour GitHub et Plane |
| Valeurs | `helm/n8n-values.yaml` |

Le mode simple suffit pour 5 à 7 personnes.

## Le secret indispensable

`N8N_ENCRYPTION_KEY` chiffre les identifiants enregistrés dans n8n (tokens GitHub, Plane…).

> ⚠️ Si cette clé est perdue, les identifiants ne sont plus lisibles, même avec une sauvegarde.

## Étapes

**1. Générer la clé** (une seule fois, avec le même mot de passe Vault)

```bash
./scripts/generate-secrets.sh n8n
```

**2. Déployer** (2 à 5 min)

```bash
ansible-playbook -i ~/.config/projectos/hosts.yml --ask-vault-pass \
  -e n8n_deploy_approved=true \
  -e @$HOME/.config/projectos/platform.yml \
  -e @$HOME/.config/projectos/n8n-secrets.vault.yml \
  infrastructure/ansible/playbooks/deploy-n8n.yml
```

**Attendu :** `n8n répond en HTTPS`, `failed=0`.

**3. Créer le compte propriétaire, tout de suite**

Ouvre `https://n8n.TON-DOMAINE/` et crée le compte.

> ⚠️ Tant qu'il n'existe pas, la première personne qui ouvre la page devient propriétaire.

## En cas de problème

| Symptôme | Action |
|---|---|
| Pod en erreur | `sudo k3s kubectl -n n8n get pods`, puis `sudo k3s kubectl -n n8n logs deploy/n8n-main` |
| Certificat bloqué | `sudo k3s kubectl -n n8n describe certificate n8n-tls` |

## Mettre à jour

1. Sauvegarder d'abord.
2. Mettre la nouvelle archive dans `helm/charts/`, puis changer la version et l'empreinte dans `deploy-n8n.yml` et `helm/charts.lock.yaml`.
3. Relancer l'étape 2.

## Retour arrière

```bash
sudo k3s kubectl -n kube-system delete helmchart n8n
```

Le volume reste. **Ne jamais** supprimer le namespace `n8n` sans sauvegarde testée.
