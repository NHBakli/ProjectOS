# 5. Déployer n8n

> ⏳ **Pas encore prêt.** Ce guide décrit ce qui est préparé.

## Ce qui est prévu

| Élément | Choix |
|---|---|
| Chart | n8n officiel `1.17.0` (n8n `2.44.5`) |
| Mode | Simple : une instance, base SQLite sur un volume de 5 Gio |
| Accès | `https://n8n.<ton-domaine>` |
| Valeurs | `helm/n8n-values.example.yaml` |

Le mode simple suffit pour 5 à 7 personnes. Pour plus de charge, il faudra passer en « queue mode », avec PostgreSQL et Redis.

## Le secret indispensable

`N8N_ENCRYPTION_KEY` chiffre les identifiants enregistrés dans n8n (tokens GitHub, Plane…).

> ⚠️ Si cette clé est perdue, les identifiants ne sont plus lisibles, même avec une sauvegarde.

Elle sera générée et stockée comme les secrets Plane, dans un fichier Vault.

## Ensuite

1. Déployer n8n.
2. Tester une sauvegarde et sa restauration, **avec la même clé**.
3. Créer un premier workflow GitHub → Plane, simple et sans doublons.
4. Ajouter le tri des tickets par label (`frontend` / `backend`).
